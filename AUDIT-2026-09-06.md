# Audit, 6 September 2026

Fourteen findings handed to the project. Working rule from `CLAUDE.md`: reproduce every finding
before acting on it, write the failing case and watch it fail first. Every item below was
reproduced against the real code, and every fix carries a test that goes red when the fix is
removed. Where I disagreed with a finding's framing I have said so rather than quietly narrowing
it.

All thirteen are fixed. The suite is 178 tests.

## Things worth recording

**The migration that item 1 forced.** Twenty-three cycles were already in cold storage with no
fingerprint. Treating a missing fingerprint as stale would have re-uploaded 138 GB. A tar does match
its record whenever the record was final before the upload ran, and both sides record their times,
so that is checked and the fingerprint adopted. Measured against the live spool: 23 adopt, 0
re-upload. A cycle whose record was still changing at upload time is re-shipped instead.

**Item 2 needed a better test than the one I wrote first.** My first version passed against the
mutation it was meant to catch, because the module records the failure rather than raising and the
final write saved the state either way. The distinguishing case is a `ship.json` write that fails
outright: with the write before the destructive steps nothing is lost, and with it after them the
tar and the local files are already gone. Only the second version fails on the mutation.

**Two test stubs were lying.** `StubOts` wrote a proof that did not contain the digest of the file
it stamped, which a real OpenTimestamps proof always does, so a check that matters would have passed
on nothing. The score fixtures built a cycle record with invented digests and no file list, so the
scorer's new verification had nothing real to verify. Both now behave like the thing they stand in
for, and several fixtures had to be corrected as a result.

**Where I narrowed a finding.** The report said the verifier "can PASS tampered provenance" and that
witnessing does not close the gap. Both are right. But a cycle that has simply not been witnessed
yet is pending, not tampered, and failing it would have made the verifier red on every fresh cycle.
So a missing proof is reported as pending; a proof that is present and does not belong to this root
is a failure.

**What this did not change.** The 5 MB globe pack is still committed on every scored cycle and still
belongs in object storage. That was already recorded before this audit and is not part of it.
